settings turn controls on, styles set values
A colour in settings.color.palette appears as a swatch a user can pick. The same colour under styles.color.background is what the site actually renders by default. Confusing the two is why themes ship palettes that nothing uses.
Custom properties are predictable
Every preset becomes --wp--preset--{category}--{slug}, and everything under settings.custom becomes --wp--custom--{path}. That naming is stable, which makes theme.json a design-token file you can rely on from plain CSS.
Specificity
Styles generated from theme.json land in a stylesheet core prints in the head, before your theme’s style.css. That means your CSS wins — but a user’s change in the Site Editor is stored separately and beats both.
