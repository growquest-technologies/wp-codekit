add_role()
Writes to the wp_user_roles option — once
Why the version matters
add_role() returns null and does nothing if the role already exists. Change the capability list in your code and nothing happens on any site that already ran it once. The generated migration stores a version number and re-applies the map whenever it changes — the difference between code that works on your machine and code that works on a client’s.

Primitive vs meta capabilities
edit_posts is primitive: it lives in the role. edit_post — singular — is a meta capability that core maps at runtime against the specific post and its author. Never store singular meta caps in a role; check them with current_user_can( edit_post, $post_id ) instead.
On uninstall
remove_role() deletes the role but leaves every user who had it with no role at all — they lose admin access entirely. The generated cleanup reassigns those users first, which is the part most plugins skip.
